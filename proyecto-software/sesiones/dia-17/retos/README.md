# Retos del Día 17 - El README

---

## Nivel base - ¿Taladro o agujero?

Para cada frase de README, di si vende el **taladro** (feature) o el **agujero** (valor), y
si hace falta, reescríbela como valor:

1. "Sistema desarrollado con PHP 8, MySQL y JavaScript vanilla."
2. "Encuentra cualquier pedido del mes en dos segundos."
3. "Base de datos normalizada con integridad referencial."
4. "Nunca más pierdas una venta por no encontrar el cuaderno."
5. "Implementa el patrón de arquitectura cliente-servidor."

---

## Nivel medio - Tu primera línea

- [ ] Escribe **una oración** que diga: qué hace, para quién, por qué importa
- [ ] Sin mencionar ninguna tecnología
- [ ] Que la entienda alguien que no programa

La prueba:

- [ ] Léesela a un compañero (o imagínate a tu abuela). ¿Entiende qué hace tu sistema?
- [ ] Si tuvo que preguntar "¿pero qué es?", reescríbela

---

## Nivel extra - Tu LEEME completo

- [ ] Primera línea en negrita
- [ ] "El problema", en idioma del cliente (sin nada técnico)
- [ ] "Qué hace": puntos con verbo y beneficio
- [ ] "Cómo se usa", para el usuario
- [ ] "Cómo instalarlo", al final, para el técnico
- [ ] Estado y límites, honestos

Y responde:

> Imagina que un empleador ve tu GitHub dentro de dos años, cuando ya no te acuerdas de este
> proyecto. ¿Tu README le alcanza para entender qué hiciste y por qué?

Si depende de que estés tú para explicarlo, el README todavía no está terminado. Un buen README
te representa cuando tú no estás.
