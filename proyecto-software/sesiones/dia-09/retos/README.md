# Retos del Día 9 - Requerimientos

Día de entrega: retos cortos.

---

## Nivel base - ¿Requerimiento o intención?

Para cada uno: ¿se puede verificar? Si no, reescríbelo.

1. "El sistema debe ser rápido y confiable."
2. "El sistema debe permitir registrar un cliente con nombre, teléfono y dirección."
3. "La interfaz debe ser amigable."
4. "El sistema debe usar PHP y MySQL."
5. "El sistema debe mostrar un mensaje de error cuando la fecha de entrega sea anterior a hoy."

**La prueba:** ¿puedes escribir un caso de prueba que dé PASA o FALLA?

*(Ojo con el 1 y el 4: cada uno tiene un problema distinto.)*

---

## Nivel medio - Tus requerimientos

- [ ] **Seis a ocho funcionales**, que cubran tus objetivos del Día 3
- [ ] Uno por fila: ninguno con "y"
- [ ] Al menos uno con **"debería"**
- [ ] **Todos con su origen**: problema, entrevista u observación

Y la verificación cruzada:

- [ ] ¿Cada objetivo del Día 3 tiene al menos un requerimiento?
- [ ] ¿Cada requerimiento sirve a algún objetivo?

Si alguno no sirve a ningún objetivo, quítalo o revisa tus objetivos.

---

## Nivel extra - Los no funcionales, con número

Vuelve a tus notas del Día 6 y saca **al menos tres** no funcionales:

| ID | Requerimiento **con número** | Cómo se verifica |
|---|---|---|

- [ ] Cada uno con un número o criterio observable
- [ ] Cada uno con su forma de verificación
- [ ] Al lado de cada uno, **de qué observación salió**

Y responde:

> Si mañana alguien tuviera que decidir si tu sistema cumple o no cada uno de estos,
> ¿podría hacerlo sin discutir contigo?

Si hace falta que tú lo interpretes, todavía no está bien escrito.
